# 运输业务闭环调研与资料收集清单

| 文档属性 | 内容 |
| --- | --- |
| 文档用途 | 业务访谈、资料收集、现状核对、需求确认及后续系统设计依据 |
| 当前版本 | V1.0 |
| 编制日期 | 2026年8月23日 |
| 适用范围 | 多厂商货物运输需求、运输计划、TMS运单与调度、实际承运、回单、应收、应付和利润核算 |

## 一、文档目标

本文件用于完整了解当前运输业务闭环，重点回答以下问题：

1. 每一件货物从哪个厂商、哪一条原始需求产生。
2. 货物经过了哪些人工整理、计划分组和系统录入。
3. 每件货物最终由哪一辆实际车辆、哪个司机完成运输。
4. 每件货物是否真实送达，有什么凭证可以证明。
5. 第三方厂商应付、实付了多少钱，款项对应哪些货物。
6. 我方应向实际承运车辆支付多少钱，预付款和尾款是否完整。
7. TMS中的整车运单、整车调度单与真实货物、真实车辆如何对应。
8. 每一批业务最终收入、成本和利润是多少。

调研完成后，应能够逐笔追溯：

```text
厂商原始计划
→ 统一货物记录
→ 运输计划
→ TMS整车运单
→ TMS整车调度单
→ 实际车辆趟次
→ 送达回执
→ 厂商付款
→ 外车预付款与尾款
→ 最终利润
```

## 二、当前已知业务现状

### 2.1 运输需求来源

- 存在多个第三方厂商。
- 厂商每天提供大量运输需求，每批通常为数百条。
- 货物主要为汽车或汽车大型配件。
- 我方业务员登录各厂商后台，导出Excel文件。
- 各厂商提供的信息大致相同，但字段名称和格式不同。

### 2.2 原始运输需求表

- 业务员将不同厂商的数据人工整理成统一Excel表格。
- 该表暂命名为“原始运输需求表”。
- 已知可能包含：厂商、名称、重量、规格、发货地、收货地、期望送达时间等字段。
- 当前理解为一行对应一个实际货物。
- 目前尚未取得真实模板，也不确定是否会拆分为多个文件或工作表。

### 2.3 运输计划表

- 业务员对原始运输需求表进行二次整理，形成多份运输计划表。
- 一份运输计划表中的货物运输线路总体一致。
- 部分货物可能在线路途经点提前卸货。
- 同一运输计划中的货物可能分配给多辆实际运输车辆。
- 实际运输车辆不属于我方，运输费用由我方承担。
- 通常先向实际车辆预付运输费的60%。

### 2.4 TMS整车运单

- 业务员原则上需要为运输计划中的每一个货物生成一张整车运单。
- 整车运单已知字段包括：发货地、收货地、名称、规格、重量、运费。
- 运费由TMS运单系统自动计算。
- TMS运单金额需要与第三方厂商支付给我方的金额保持一致。
- 当前可能通过调整重量或其他计价参考字段，使TMS计算金额与厂商金额一致。
- 每张整车运单带有支付码，第三方厂商可通过支付码付款。
- 实际操作中，为减少录入工作量，业务员可能将数百个货物合并成一张整车运单。

### 2.5 TMS整车调度单

- 业务员在TMS调度中心创建整车调度单。
- 创建调度单时，需要将整车运单装载到调度单中。
- 已知字段包括：车牌号、司机、电话、所属公司、包车费。
- 包车费需要与我方支付给实际运输车辆的运输费用保持一致。
- TMS调度单目前只能填写一个车牌号。
- 该车牌号可能不是实际运输车牌号。
- 一张调度单在真实业务中可能对应多辆实际运输车辆。

### 2.6 送达与回执

- 业务员人工确认每个货物的送达情况。
- 业务员人工获取收货回执单。
- 确认所有货物均送达后，业务员人工将TMS调度单设置为“已送达”。

### 2.7 结算与付款

- 调度单设置为“已送达”后，TMS调度中心触发结算。
- 财务人员需要审核结算。
- 因TMS运单数量与实际货物数量可能不匹配，财务需要在线下向业务员核实送达真实性。
- 审核通过后，款项支付给调度单所属公司，该公司大概率为我方子公司。
- 业务员随后向实际运输车辆支付剩余40%运输费。

### 2.8 基本利润关系

当前业务的基本盈利关系应为：

```text
厂商支付的整车运单费
＞ 实际车辆运输费用 + 其他业务成本
```

```text
业务利润
= 厂商实际支付金额
- 实际车辆最终运输费
- 其他实际成本
```

需要区分以下四种金额，不能使用同一个字段混合记录：

1. 厂商约定支付金额。
2. TMS整车运单计算金额。
3. TMS整车调度单包车费。
4. 实际车辆最终运输费用。

## 三、当前最核心的信息缺口

当前最大缺口不是单个字段缺失，而是缺少真实货物、系统单据、实际车辆、回执和资金之间的稳定对应关系。

至少需要建立以下完整追溯链：

| 环节 | 建议唯一标识 |
| --- | --- |
| 厂商原始需求 | 厂商代码 + 厂商原始计划编号 |
| 实际货物 | 统一货物编号；汽车优先使用VIN，配件需要业务唯一编号 |
| 运输计划 | 运输计划编号 |
| TMS整车运单 | TMS整车运单号 |
| TMS整车调度单 | TMS整车调度单号 |
| 实际运输 | 实际车辆趟次编号 |
| 送达凭证 | 回执编号或签收凭证编号 |
| 厂商收款 | 支付码交易号、银行流水号 |
| 外车付款 | 预付款流水号、尾款流水号 |

目前至少缺少两张关键映射表：

1. **整车运单—实际货物对应表**：解决“一张整车运单包含数百个真实货物”的问题。
2. **整车调度单—实际车辆趟次对应表**：解决“一张调度单只有一个车牌，但实际由多辆车运输”的问题。

## 六、各环节核对规则

### 6.1 厂商原表与统一需求表

核对内容：

- 厂商原始总行数与统一表记录数。
- 厂商原始计划编号是否全部保留。
- 是否存在重复、遗漏或无来源的新增记录。
- 名称、重量、规格、起讫地和时效是否被错误修改。
- 修改字段是否能够追溯原值、修改人和修改原因。

建议结果分类：通过、重复、缺失、字段异常、待人工确认。

### 6.2 统一需求表与运输计划表

核对内容：

- 每个货物是否恰好分配到一个有效运输计划。
- 是否存在未分配、重复分配或已取消仍分配的货物。
- 计划中的货物总数和总重量是否与来源记录一致。
- 线路、途经点和期望时效是否兼容。
- 计划调整后是否留下版本和操作记录。

### 6.3 运输计划与TMS整车运单

核对内容：

- 每个计划中的货物是否均有对应TMS运单。
- 一张TMS运单包含哪些实际货物。
- TMS运单货物数量、重量和线路如何代表其包含的真实货物。
- TMS运单金额是否等于对应厂商约定金额合计。
- 为对齐金额而调整的字段、人员、时间和原因。

### 6.4 TMS调度单与实际车辆

核对内容：

- 每张调度单实际使用了多少辆车。
- 每辆实际车辆装载了哪些货物。
- 系统车牌与真实车牌的关系。
- 包车费是整张调度单金额，还是多辆实际车辆费用之和。
- 实际换车、换司机或增加车辆后是否同步记录。

### 6.5 实际货物与回执

核对内容：

- 每个实际货物是否存在送达结果。
- 每个已送达货物是否有有效回执。
- 回执中的货物、收货地点和签收时间是否匹配。
- 一张回执包含多个货物时是否有清晰明细。
- 未送达或回执不合格的货物是否阻止整单完成。

### 6.6 TMS应收与厂商到账

核对内容：

- TMS运单应收金额与厂商约定金额。
- 支付码交易金额与银行实际到账金额。
- 一笔到账具体对应哪些运单和货物。
- 部分付款、合并付款、退款和付款主体变化。
- 应收、实收、未收和退款金额是否平衡。

### 6.7 外车应付与实际付款

核对内容：

- 实际承运约定价与TMS调度单包车费。
- 60%预付款的金额、时间、收款人和银行流水。
- 40%尾款的支付前提和实际支付记录。
- 扣款、增补费用和最终应付金额。
- 预付款加尾款是否等于最终实付金额。

### 6.8 收入、成本与利润

建议分别计算预计和实际结果：

```text
预计利润
= 厂商约定收入
- 外车约定运输费
- 预计其他成本
```

```text
实际利润
= 厂商实际到账金额
- 外车实际支付金额
- 实际其他成本
- 退款及赔付
```

需要确定收入和成本如何分摊到货物、线路、车辆、调度单和厂商。

## 七、金额和付款待确认事项

### 7.1 厂商应收

- [ ] 厂商金额按货物、运单、批次、合同还是账期计算。
- [ ] 厂商是否提供明确的单货物金额。
- [ ] TMS运费为什么必须通过修改重量等参数对齐。
- [ ] 是否允许直接录入厂商确认金额。
- [ ] 厂商途中增补、扣款或赔付如何处理。
- [ ] 厂商付款与支付码之间是一对一还是多对多关系。

### 7.2 外车应付

- [ ] 实际运输费按车辆、趟次、线路还是批次确定。
- [ ] 包车费是否等于多辆实际车辆费用之和。
- [ ] 60%是在派车、装车还是发车时支付。
- [ ] 40%是在部分送达、全部送达、回执齐全还是财务审核后支付。
- [ ] 未完成运输时预付款如何退回或抵扣。
- [ ] 途中增加车辆、改线或等待产生的费用如何审批。

### 7.3 支付码灵活性

需要重点确认：

- [ ] 支付码由哪个系统和主体生成。
- [ ] 支付码绑定运单、客户、金额还是收款账户。
- [ ] 金额是否固定。
- [ ] 是否支持多次付款。
- [ ] 是否支持多个付款方。
- [ ] 是否支持跨运单、跨批次合并付款。
- [ ] 支付码是否有有效期。
- [ ] 退款后原支付码能否继续使用。
- [ ] 到账后TMS是否自动更新，还是需要人工认领。

## 八、运输执行与异常待确认事项

- [ ] 如何选择实际车辆、司机和承运商。
- [ ] 是否签订一车一合同、一趟一合同或批量合同。
- [ ] 一辆车一天是否可以执行多个趟次。
- [ ] 装车后是否允许换车、换司机或换线路。
- [ ] 实际装车数量少于或多于计划时如何处理。
- [ ] 途经点的卸货顺序是否固定。
- [ ] 部分货物送达、部分未送达时调度单是什么状态。
- [ ] 拒收、破损、丢失、返程和二次配送如何处理。
- [ ] 延误是否产生罚款或客户扣款。
- [ ] 是否记录装车、发车、到达、签收等节点时间。
- [ ] 异常是否影响尾款或厂商应收。

## 十一、建议的业务访谈对象

建议分别访谈以下人员，避免只依据单一岗位描述流程：

1. 负责从厂商后台导出数据的业务员。
2. 负责整理运输计划和分配车辆的调度人员。
3. 负责TMS整车运单录入的人员。
4. 负责TMS整车调度单录入的人员。
5. 负责联系实际车辆及支付预付款、尾款的业务员。
6. 负责回执收集和送达确认的人员。
7. 负责TMS结算审核的财务人员。
8. 负责银行收付款、开票和会计处理的财务人员。
9. 我方子公司的业务或财务负责人。
10. 必要时访谈一个第三方厂商和一个实际承运商。

## 十二、首批资料收集顺序

第一轮建议优先取得以下九项材料：

1. 每个厂商一份真实导出表。
2. 当前统一的原始运输需求表。
3. 一份真实运输计划表。
4. 同批次对应的TMS整车运单导出。
5. 同批次对应的TMS整车调度单导出。
6. 实际车辆及实际装车分配表。
7. 同批次对应的全部收货回执。
8. 厂商付款、实际车辆60%预付款和40%尾款凭证。
9. 业务员和财务当前使用的核对表、操作说明或截图。

首批样本应选择一个已经完成运输、回执、厂商收款和外车付款的真实批次，以便完整复盘。

## 十三、调研完成标准

只有同时满足以下条件，才可以认为已完整了解现有业务闭环：

- [ ] 能从任意一条厂商原始需求追溯到实际货物。
- [ ] 能说明该货物被分配到哪份运输计划。
- [ ] 能找到对应的TMS整车运单和整车调度单。
- [ ] 能确认由哪辆真实车辆、哪个司机运输。
- [ ] 能找到有效的送达回执。
- [ ] 能说明厂商应付和实际到账金额。
- [ ] 能说明实际车辆应付、60%预付款和40%尾款。
- [ ] 能解释TMS车牌与真实车牌的差异。
- [ ] 能解释TMS运单数量与实际货物数量的差异。
- [ ] 能计算该货物、该计划或该批次的实际利润。
- [ ] 所有不一致都有明确的处理人、审批规则和处理凭证。
- [ ] 合同主体、收付款主体、开票主体和TMS所属公司关系清楚。

最终应能够对任意一个已完成批次准确回答：

> 有哪些货物、从哪里来、由谁运输、是否送达、有什么凭证、厂商付了多少、实际车辆收了多少、其他成本是多少、最终赚了多少，以及每一个数字和状态由什么材料证明。
