# 统一术语与系统组件用户说明（MVP最终版）

| 文档属性 | 内容 |
| --- | --- |
| 版本 | V1.0 |
| 日期 | 2026年8月24日 |
| 适用范围 | MVP需求、原型、接口、数据库、测试和业务培训 |

## 一、统一口径

1. 委托运输并向我方支付费用的企业统一称为“委托厂商”。
2. 一条运输需求对应一件货物和一张内部运单。
3. “运输任务”表示一次可执行的业务安排；“执行单元”表示最小的真实履约单元。
4. 三类业务共用一套对象模型，不再分别建立三套互不相通的单据。
5. 客户应收和承运应付必须分开，不能用同一个“运费”字段表示收入和成本。
6. 第一阶段只有内部运营管理后台，没有司机端、承运商门户或委托厂商门户。

## 二、业务分类术语

| 统一术语 | 定义 |
| --- | --- |
| 整车业务 | 我方同时组织承运车辆和司机完成货物取送，通俗称“出人车” |
| 板车运输 | 使用专用板车装载商品车或大型配件运输，通俗称“出车” |
| 自驾运输 | 我方组织司机直接驾驶厂商商品车到目的地，通俗称“出人” |
| 单车地跑 | 一辆商品车绑定一名司机单独执行的自驾运输 |
| 编组跑路 | 多辆商品车组成车队执行的自驾运输，逐车逐司机绑定 |
| 背载 | 母车承载子车共同执行的自驾运输 |
| 开送/总驾 | 自驾运输的业务称谓或服务标签，不是独立一级业务类型 |

## 三、核心业务对象

| 现状叫法 | 目标统一术语 | 定义 |
| --- | --- | --- |
| 第三方厂商、客户、厂家 | 委托厂商 | 向我方提出运输需求并支付客户运费的企业 |
| 厂商导出表、原始表 | 厂商原始需求文件 | 从厂商后台原样导出的Excel或接口报文 |
| 每日统一Excel | 导入批次 | 某厂商、项目在某次导入中的原始文件和处理结果集合 |
| 表格一行、厂商计划 | 运输需求 | 委托厂商提出的一件货物运输要求 |
| 汽车、商品车、配件 | 货物 | 被运输或需要交付的实物对象 |
| 被运的车 | 商品车/被运输车辆 | 货物的一种；在自驾场景中也可充当行驶车辆 |
| 目标系统一货一单 | 内部运单 | 由一条标准运输需求生成的内部业务单据 |
| 线路表、运输计划表 | 运输计划 | 对多张内部运单进行线路、途经点和时间编排的方案 |
| 整车调度单、派车单 | 运输任务 | 对一组运输需求进行派车和履约的可执行安排 |
| 车队、编组 | 执行编组 | 将多个执行单元组织在一起的可选对象 |
| 一辆车一趟、一个自驾车 | 执行单元 | 最小真实履约单元，保存本次人员、车辆和货物关系 |
| 外车、司机、派车公司 | 履约资源 | 承运方、司机、车辆等可参与运输执行的资源档案 |
| 装车表、背车关系 | 装载/编组关系 | 货物装载、编组成员及母车子车之间的真实关系 |
| 收货回执、POD照片 | 签收凭证 | 收货方签字、盖章、照片或文件等原始证明 |
| 回单 | 电子回单 | 系统内关联货物、签收凭证和审核结果的记录 |
| 厂商付的钱、整车运单费 | 客户应收 | 委托厂商应向我方支付的业务收入 |
| 包车费、司机费用、外车费用 | 承运应付 | 我方应向实际履约方支付的业务成本 |
| 支付码 | 客户付款码 | 厂商付款使用的渠道或识别标识，不等同于应收单 |
| 预付60% | 承运预付款 | 承运开始前或装车后支付的部分成本，比例按合同配置 |
| 剩余40% | 承运尾款 | 送达、回单及审核条件满足后支付的剩余成本 |
| 推送财务的附件和金额 | 结算资料 | 由运输系统生成并提交现有结算系统的业务依据 |

## 四、核心对象关系

```text
委托厂商
  → 导入批次
  → 运输需求（1件货物）
  → 内部运单（1货1单）
  → 运输计划（1-N张内部运单）
  → 运输任务（1-N个执行单元）
  → 执行编组（可选）
  → 真实司机、车辆、承运方、装载/编组关系
  → 逐货送达、电子回单和异常
  → 客户应收、承运应付和结算资料
```

不同业务下的执行单元：

| 业务类型 | 执行单元表达 |
| --- | --- |
| 整车业务 | 1辆承运车辆 + 1名司机 + 1-N件货物 |
| 板车运输 | 1辆板车 + 1-N件商品车/配件；司机和责任来源按项目配置 |
| 自驾-单车 | 1辆商品车 + 1名司机；商品车同时是货物和行驶车辆 |
| 自驾-编组 | N个单车执行单元 + 1个可选执行编组 |
| 自驾-背载 | 母车、子车、司机及对应运输需求的关联关系 |

## 五、MVP目标用户

| 用户角色 | 是否直接使用MVP | 主要工作 |
| --- | --- | --- |
| 业务专员/项目人员 | 是 | 导入需求、修正异常、维护项目数据和内部运单 |
| 调度员/项目主管 | 是 | 编制计划、合单、试算价格、建立任务并派车 |
| 驻厂人员 | 是 | 核验货物、司机和车辆，登记保险、临牌及发车结果 |
| 运踪人员 | 是 | 根据电话、微信、短信反馈登记节点和异常 |
| 回单人员 | 是 | 上传、审核、驳回和补传电子回单 |
| 签单结算员 | 是 | 核对客户应收、付款码和客户侧结算资料 |
| 外车结算员 | 是 | 核对承运应付、预付款、尾款和承运侧结算资料 |
| 业务经理 | 是 | 审批改价、费用增补、异常和利润倒挂 |
| 系统管理员 | 是 | 用户、权限、字典、项目模板、接口和日志管理 |
| 管理层 | 是 | 查看履约、收入、成本、毛利和异常报表 |
| 财务审核员 | 否，使用现有结算/财务系统 | 审核、对账、开票、收付款和记账 |
| 司机/承运商 | 否，通过线下沟通参与 | 提供人员车辆信息、反馈运输节点和回单 |
| 委托厂商人员 | 否，使用厂商后台 | 下达需求、查询厂商侧结果、支付及接收回单 |
| 收货方 | 否 | 验收货物并提供签收凭证 |

## 六、前端组件与目标用户

MVP只建设一个“内部运输运营管理后台”，按角色显示以下功能组件：

| 前端组件 | 主要用户 | 主要用途 |
| --- | --- | --- |
| 数据导入与需求 | 业务专员、项目人员 | 批次导入、字段映射、纠错去重、需求和内部运单查询 |
| 运输计划与价格 | 调度员、项目主管、业务经理 | 人工合单、线路/途经点、业务分类、价格试算和改价审批 |
| 履约资源与派车 | 调度员、驻厂人员 | 司机、车辆、承运方档案，运输任务、执行单元和派车绑定 |
| 人工运踪与回单 | 驻厂、运踪、回单人员 | 核验发车、人工登记节点、异常处理、回单审核和补传 |
| 结算资料与状态 | 签单结算员、外车结算员、业务经理 | 应收应付、预付尾款、毛利检查、结算推送和状态查询 |
| 基础配置与管理 | 系统管理员、管理层 | 项目合同、字段模板、价格规则、权限、日志和基础报表 |

## 七、后端组件与服务用户

| 后端组件 | 主要服务用户 | 主要职责 |
| --- | --- | --- |
| 厂商数据接入 | 业务专员 | Excel/API接入、原文件、批次、字段模板和失败重处理 |
| 客户/项目/合同/资源 | 业务专员、调度员、系统管理员 | 委托厂商、项目、合同、承运方、司机和车辆档案 |
| 需求与内部运单 | 业务专员、结算员 | 一需求一货物一运单及来源追溯 |
| 运输计划与合单 | 调度员、项目主管 | 待计划池、人工编排、线路顺序、价格试算和计划锁定 |
| 派车与履约执行 | 调度员、驻厂、运踪人员 | 任务、执行单元、编组、资源绑定、核验和履约状态 |
| 运踪/回单与异常 | 运踪、回单人员 | 人工节点、逐货回单、异常、业务门禁和处理闭环 |
| 结算资料集成 | 签单结算员、外车结算员、财务审核员 | 应收应付、预付尾款、毛利校验、推送及结果回写 |

公共支撑能力包括：Excel导入引擎、价格规则与审批、文件与影像、权限与审计、状态机与业务门禁。

## 八、外部系统和人工渠道

| 外部对象 | 与MVP的关系 |
| --- | --- |
| 厂商后台 | 业务人员人工导出需求、按厂商要求回传回单；后续可逐厂商接API |
| 现有结算系统 | 接收结算资料，完成审核、对账、开票、收付款并向金蝶处理 |
| 电话/微信/短信 | 第一期司机和承运商运输反馈渠道，由内部人员代录系统 |
| 金蝶 | 继续由现有结算/财务链路对接，MVP原则上不直接替换 |

## 九、权限原则

- 业务人员只能查看其负责的厂商和项目数据。
- 调度和驻厂人员只能操作已授权项目的计划、任务和执行单元。
- 价格调整、途中增补、利润倒挂和结算重推必须经过授权或审批。
- 回单上传与回单审核应尽量分权，并记录审核人和时间。
- 财务实际收付款结果以现有结算/财务系统回写为准。
- 管理层默认只读；系统管理员不能代替业务或财务审批。

## 十、禁止继续使用的模糊表述

| 不再单独使用 | 应改为 |
| --- | --- |
| 车辆 | 明确写商品车/被运输车辆、承运车辆、板车、母车或子车 |
| 运费 | 明确写客户应收、承运应付、预付款、尾款或增补费用 |
| 运单 | 明确写内部运单、运输任务或现有TMS整车运单 |
| 调度单 | 目标系统统一写运输任务；涉及旧系统时写现有TMS调度单 |
| 回单 | 区分原始签收凭证和系统电子回单 |
| 已完成 | 明确写货物已送达、回单已齐、任务已完成或结算已完成 |

如后续需要新增术语，必须先说明它与运输需求、内部运单、运输计划、运输任务和执行单元的关系，再进入产品和研发文档。
