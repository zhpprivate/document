# 需求覆盖评审与重设计说明（业务分类修正版）

## 一、修正结论

最新需求对业务分类作了明确修正。整个运输管理系统的一级业务类型应直接分为三类：

| 一级业务类型 | 通俗口径 | 业务含义 |
| --- | --- | --- |
| 整车业务 | 出人车 | 收到运输计划后，同时派承运车辆和司机取货、送货 |
| 板车运输 | 出车 | 我方提供专用板车运力，商品车或大型配件作为货物装载运输 |
| 自驾运输 | 出人 | 我方提供司机，直接驾驶厂商提供的商品车到目的地，属于开送/总驾服务 |

其中，自驾运输再分为单车地跑、编组跑路和背载三种执行子类型。开送/总驾不再归入“整车项目”的下级场景；“出人车、出车、出人”也不再作为可以任意组合的独立资源维度，而是三类一级业务的直接业务含义。

上一版设计中的统一执行模型、逐货回单和双向结算设计仍然合理，可以继续使用；需要重做的是业务分类、资源校验、价格维度及相关组件文案。本次另行生成修正版文件，没有修改原文件和上一版文件。

## 二、统一业务模型

三类业务共用以下主模型：

```text
运输需求（1件货物1条记录）
  -> 运输计划（合单和线路方案）
  -> 运输任务（1-N条需求）
  -> 执行编组（可选，仅在需要编组时使用）
  -> 1-N个执行单元
  -> 车辆、司机、承运方、货物及装载/编组关系
```

系统中的“运输任务”和“执行单元”是跨业务共用的编排对象，不等同于某一种业务类型。不同业务通过同一模型按以下方式落地：

| 业务类型/子类型 | 执行单元表达 | 必须记录的关系 |
| --- | --- | --- |
| 整车业务（出人车） | 1辆承运车 + 1名司机 + 1-N件货物 | 车辆、司机、货物、线路和装卸顺序 |
| 板车运输（出车） | 1辆板车 + 1-N件商品车/配件 | 板车与货物的装载关系；司机及责任来源按项目约定 |
| 自驾-单车地跑 | 1辆商品车 + 1名司机 | 商品车同时是货物和本次行驶车辆 |
| 自驾-编组跑路 | N个单车执行单元 + 1个可选执行编组 | 逐车逐司机绑定、领队、统一线路和编组成员 |
| 自驾-背载 | 关联母车和子车的执行单元 | 母子车、固定、装卸及对应运输需求 |

车辆的承运车、板车、自驾车、母车、子车身份是本次执行中的角色，不永久固化在车辆档案中。

## 三、设计调整

### 1. 业务分类

- `business_type`只允许：整车业务、板车运输、自驾运输。
- `self_drive_subtype`只在自驾运输时使用：单车地跑、编组跑路、背载。
- 开送/总驾作为自驾运输的业务称谓或服务标签，不与一级业务类型并列。
- 不再设置可独立组合的“资源提供模式”。派车资源校验直接由`business_type`驱动。

### 2. 任务和派车

- 整车业务必须同时具备车辆和司机后才允许发车。
- 板车运输必须绑定板车及装载清单；“只出车”场景中的板车驾驶方、承运主体和事故责任需要按项目配置。
- 自驾运输必须逐商品车绑定司机；编组增加执行编组，背载增加母子车装载关系。
- 一个运输任务可以包含一个或多个执行单元，不再强制等于一辆车或一个司机。

### 3. 价格和结算

- 客户合同价和客户应收仍以运输需求为基础。
- 履约应付以执行单元计算、按运输任务汇总，保留逐单明细。
- 价格规则扩展维度改为“项目 + 业务类型 + 自驾子类型”，不再引用独立资源模式。
- 最终客户结算价 = 合同约定价 + 审批通过的途中增补价。
- 预付款比例、尾款比例和支付节点按项目/合同配置，不写死为60%和40%。

## 五、组件划分结论

现有分层可以覆盖最新需求，但以下组件必须理解为按三类业务驱动：

- 计划与价格中心：保存一级业务类型和自驾子类型，并据此选择价格规则。
- 任务、编组与执行单元：统一承载整车、板车和自驾三类业务。
- 履约资源与派车：按业务类型校验所需车辆、司机和承运方，不单独判断资源模式。
- 装载/编组关系：同时支持板车装载、自驾编组和背载母子车。
- 客户应收与履约应付：继续分开建模，避免客户货物数、内部运单数和实际执行单元数不一致时无法核账。

一期仍应覆盖Excel/API导入、项目字段模板、人工/规则合单、价格试算、三类业务派车、逐货回单、预付/尾款、应收应付、审批及财务适配。智能优化、司机端、承运商门户、持续定位和高级异常预警继续作为二期或待定能力。

## 六、仍需业务确认

1. 板车运输“只出车”时，板车驾驶员由厂商、我方承运商还是其他主体提供，司机费用是否包含在板车结算价中。
2. 整车业务中的车辆和司机由同一承运方提供还是允许分别来自不同主体。
3. 编组跑路是否始终一车一司机，是否允许运输途中换驾；若允许，需要增加换驾记录。
4. 背载是否允许一辆母车背载多辆子车，是否存在途中变更母子关系。
5. 三类业务分别按车辆、司机、商品车、里程还是任务计价，不同项目是否允许配置不同规则。
6. 编组和背载的回单是逐车逐货，还是允许一份凭证覆盖多件货物。
7. 保险、临牌、油费、路桥费及事故责任在三类业务中分别由哪一方承担。

这些问题不影响总体架构，但会影响详细字段、派车校验、计价规则、合同条款和验收口径，应在详细设计前逐项确认。
